# Personal site

Zola static site (home, blog, resume, projects, 404) with a hand-written
theme, deployed to GitHub Pages (https://redroy44.github.io) from `master` by
GitHub Actions. `README.md` is the full guide.

This repository is public. Anything pushed is readable: drafts, commit
messages, history. `ideas/backlog.md` is git-ignored for that reason. Do not
commit secrets or private details, and do not add the author's email address
anywhere unless they ask.

## Facts that are easy to get wrong

- Zola is pinned to 0.23.6 in `mise.toml`. Templates are **Tera v2**: no
  macros or shortcodes, tests take keyword arguments
  (`is starting_with(pat=...)`), index arrays with `[0]` and slice with
  `[:5]`. Check https://keats.github.io/tera/ before writing template code;
  most Zola snippets online are for the older engine.
- Content is not templated (`skip_content_templating` in `zola.toml`), so
  `{{`, `{%` and `{#` are safe in posts.
- Syntax highlighting is Zola's built-in giallo with class output; an unknown
  language tag fails the build on purpose.
- Resume and projects are data-driven: edit `data/resume.toml` and
  `data/projects.toml`, not the templates.
- Link-preview images are generated by `mise run og` into `static/img/og/`
  (git-ignored). It needs a Chromium-based browser and is non-fatal without
  one.
- The only script is `static/js/site.js` (theme switch, copy buttons) plus a
  few lines in `<head>` that apply a stored theme. Every page must keep
  working without JavaScript. No frameworks and no third-party requests
  unless the author asks.
- Dark theme tokens appear twice in `static/css/style.css` (system dark, and
  the manual switch). Change both.
- CI fails on broken internal links (`zola check`) and invalid HTML
  (`mise run validate`). Run both before pushing template changes.

## Working here

- Use the mise tasks (`mise tasks` lists them): `serve`, `drafts`, `build`,
  `check`, `validate`, `og`, `new-post`, `set-domain`.
- After changing templates or CSS, build and look at the result at phone and
  desktop widths in light and dark before reporting it done.
- The author writes all site content. Leave `PLACEHOLDER` text for them, and
  do not write posts, bio or resume entries unless asked.
- Never remove `draft = true` from a post, and do not push to `master`,
  without the author's explicit go-ahead.
